# 礼包与贸易预设

普通玩家使用 `/gifts` 查看礼包、触发条件、内容和领取状态；BQ 解锁型礼包也可使用 `/gifts claim <ID>` 领取。旧的新手宝箱物品与已领取标记保留兼容。礼包包裹绑定领取者，不能用复制的包裹重复兑换。

## 可视化配置礼包

单人存档拥有者或专用服务器 OP4 可在礼包目录中新增、编辑、删除礼包，配置名称、像素图标或物品图标、必得物品、随机物品池、不重复抽取数量、NBT 和无线 EU。图标、奖励幽灵槽支持从背包和 NEI 选择物品，不消耗原物品。修改草稿后点击保存；其他管理员同时保存产生版本冲突时，需要重新载入再编辑。

触发条件有三种：

- 首次入服：仅发给首次被本系统记录登录的账号。新增这种礼包不会向已有账号追发；原 `starter` 保留旧领取标记与明确管理员重置的兼容行为。
- BQ 解锁后手动领取：任务完成后可在 `/gifts` 领取。
- BQ 首次完成自动发放：记录完成事件当时的团队成员，包括离线成员；离线成员下次登录时补发。每个玩家与礼包 ID 只授予一次，换队和任务重置不会再次领取。

BQ 任务 ID 使用与猫猫贸易机相同的解析规则。任务不存在、格式错误或 BQ 不可用时不会放行。默认礼包包括新手、蒸汽、LV、MV、HV、EV、IV、LuV；时代入口绑定 GTNH 2.9.0-RC-2 的任务 `44 / 88 / 1148 / 160 / 176 / 213 / 1493`。自定义任务库需要自行调整绑定。

定义保存在 `config/gtit/gifts.json`。首次迁移读取旧 `gift_config.json`；之后以新定义为准，旧 `gift certain/random/reset` 指令继续修改新手礼包。默认礼包更新支持作者声明的强制更新与推荐更新，并提供保留或接受更新的操作。删除的默认礼包不会在日常启动时自动重生。

背包满时包裹留在待发队列，不生成掉落物。大礼包可以分批打开；剩余内容、取出进度和玩家库存共同保存。无线 EU 使用十进制非负整数，存入授予记录锁定的 GT 无线网络所有者，只有最后一批奖励完成时支付，并通过持久收据避免重放。

## 贸易预设

默认按 **I** 打开，按键可在游戏控制设置中修改；也可由有权限的管理员使用 `/gtit presets`。首次提示延迟 160 tick，按存档与玩家记录。专用服务器只有 OP4 收到提示并可配置，单人模式允许存档拥有者配置。

预设沿用现有贸易配置，作用于当前游戏实例或服务器。同一客户端的不同单人存档共用实例内的贸易配置；首次提示仍按各存档分别记录。

`MiaoTrade/<ID>.json` 位于实际游戏目录，专用服务器使用自己的实例目录。首次放入三个模板：

- `gtit-ae-basic`：AE 基础；与 AE 强化互斥。
- `gtit-ae-advanced`：AE 强化；与 AE 基础互斥。
- `gtit-base-decoration`：基地装饰。

这三份内置文件是可编辑流程的空模板。丰富贸易内容在 `GT-MIAO-Web-BQ-Trade` 的 Web 编辑器内审核：启动程序后，在工作区列表中分别选择 `gtit-ae-basic`（18 条）、`gtit-ae-advanced`（32 条）或 `gtit-base-decoration`（32 条），再进入 GTIT 贸易编辑器。每份工作区位于 `workspace/gtit/<ID>/`，包含程序识别的 `manifest.json`、`pages.json` 和 `tab_<ID>.json`，可直接编辑、保存与导出；这些候选内容尚未自动装入玩家配置。

Web 编辑器导出的是 `config/gtit/trade/**` 配置，可用于检查和部署页面及交易。游戏预设使用的 `MiaoTrade/<ID>.json` 还包含预设 ID、名称、图标和互斥关系，不能将 Web 导出的 ZIP 或 `pages.json` 直接改名作为预设。候选预设原件与研究证据保留在编辑器仓库的 `plan/review/gtit-trade-presets-v1.8.93/`，审核后的内容再按预设格式整理。

可选择多个兼容预设。互斥关系以稳定 ID 声明，任意一方声明即生效。界面可从已有标签页制作新预设，填写 ID、名称、描述、互斥 ID 和幽灵物品图标。编辑、复制未启用的预设时默认保留原内容；明确切换后才从当前标签页替换内容。内置模板请使用新 ID 另存，已有自定义预设的 ID 固定。

应用会安装独立标签页。撤选只删除预设仍然拥有且完全未修改的页面与交易；已修改的页面保留为用户内容。保存、选择与重载具有版本冲突检测，磁盘事务日志用于中断恢复。绑定 BQ 的预设需要任务真实存在，缺失任务和卸载依赖 Mod 时不会放行。

## 关闭内置默认内容

编辑 `config/gtit/default_content.cfg` 后重启实例：

```text
defaults {
    B:loadDefaultTradeGroups=false
    B:loadDefaultLottery=false
    B:loadDefaultGifts=false
}
```

三个开关互相独立，默认均为 `true`。关闭后不注入相应内置内容，保留用户配置与礼包授予记录。贸易开关也覆盖旧 42 条交易的回退路径及 GTIT 自带贸易资产；自定义预设仍可使用。抽奖空配置保持为空，已经编辑过的卡池保留。礼包关闭不会使已经领取的有效包裹丢失。

## 自动化验证入口

启用专用测试维度后可运行：

```text
gtitlab run native-gift-system
gtitlab run native-trade-presets
gtitlab run native-preset-catalog-check
```

前两个也包含在默认 `suite` 中。第三个只检查审核稿中的注册项、元数据及任务，不安装贸易。JSON 报告区分 PASS、FAIL、SKIP；服务端建树检查不能替代真实客户端的布局、动画、NEI 拖拽及快捷键验收。
