# 礼包与贸易预设

普通玩家使用 `/gifts` 查看礼包、触发条件、内容和领取状态；BQ 解锁型礼包也可使用 `/gifts claim <ID>` 领取。旧的新手宝箱物品与已领取标记保留兼容。礼包包裹绑定领取者，不能用复制的包裹重复兑换。

## 可视化配置礼包

单人存档拥有者或专用服务器 OP4 可在礼包目录中新增、编辑、删除礼包，配置名称、像素图标或物品图标、必得物品、随机物品池、不重复抽取数量、NBT 和无线 EU。管理页独立于终端，沿用 480×330 布局；礼包目录在左侧按每页 6 项显示，右侧显示所选礼包详情。管理窗口统一使用猫猫次元口袋 C2 的棕金布纹、铜框、物品槽和币条材质，按钮沿用 C2 五态。32 个礼包壳均使用 24×24 静态 RGBA 图标与半像素深灰描边，其中 8 个时代礼包取消旧动画，原注册 ID 保持不变。独立图标未设置时继承礼包载体图标，显式设置的自定义图标会保留。图标和奖励幽灵槽支持从背包与 NEI 选择物品，不消耗原物品。

礼包编辑器分为基础、必给和随机三页，条目按每页 4 项分页；物品奖励通过物品槽配置，并可填写数量与 SNBT。草稿可保存或放弃；有未保存修改时关闭会触发保护。终端交互保持不变。

触发条件有三种：

- 首次入服：仅发给首次被本系统记录登录的账号。新增这种礼包不会向已有账号追发；原 `starter` 保留旧领取标记与明确管理员重置的兼容行为。
- BQ 解锁后手动领取：任务完成后可在 `/gifts` 领取。
- BQ 首次完成自动发放：记录完成事件当时的团队成员，包括离线成员；离线成员下次登录时补发。每个玩家与礼包 ID 只授予一次，换队和任务重置不会再次领取。

BQ 任务 ID 使用与猫猫贸易机相同的解析规则。任务不存在、格式错误或 BQ 不可用时不会放行。默认礼包包括新手、蒸汽、LV、MV、HV、EV、IV、LuV；时代入口绑定 GTNH 2.9.0-RC-2 的任务 `44 / 88 / 1148 / 160 / 176 / 213 / 1493`。自定义任务库需要自行调整绑定。

蒸汽礼包的 `bread`、`torch`、`pearl`、`coin` 奖励已替换为：`gregtech:gt.blockcasings` meta `10` 镀铜/青铜镀层砖 ×16；Potin 粗青铜合金 `pipeHuge`（`gregtech:gt.blockmachines` meta `30729`）×32；普通 `pipeMedium`（同物品 meta `30727`）×256；HP solar（同物品 meta `114`）×2。LV、MV、HV、EV、IV、LuV 礼包各包含对应电压等级的机器外壳 ×4、水泵 ×4、传送带 ×4、马达 ×8，替换原时代奖励而非追加。

定义保存在 `config/gtit/gifts.json`。首次迁移读取旧 `gift_config.json`；之后以新定义为准，旧 `gift certain/random/reset` 指令继续修改新手礼包。本轮默认礼包内容版本仍为 V2，物资数量不变；版本不随 Mod 的每个小版本自动递增。管理页常驻“查看默认更新”入口，显示已记录版本、可用版本及默认内容差异。`SKIP` 或关闭更新提醒后仍可从此入口查看并接受更新；默认礼包库关闭时该入口只读，不会暗自重新启用礼包。V2 推荐更新可选择接受、跳过此版本或关闭提醒；强制更新在应用后等待确认。执行 `APPLY` 前需要确认，确认后恢复全部 8 个默认礼包，包括被手动修改或删除的默认项，同时保留自定义礼包与领取记录。`starter` 奖励保持不变；已发放礼包的奖励快照不追溯修改，旧世界对默认礼包的手动编辑会保留到确认更新。旧版 JSON 缺少 `defaultsInitialized` 标记时会依据已有礼包定义补初始化状态，保护现有内容；重新启用默认库时重新评估推荐更新，不会因 Mod 小版本更新反复提示。

背包满时包裹留在待发队列，不生成掉落物。大礼包可以分批打开；剩余内容、取出进度和玩家库存共同保存。无线 EU 使用十进制非负整数，存入授予记录锁定的 GT 无线网络所有者，只有最后一批奖励完成时支付，并通过持久收据避免重放。

## 贸易预设

默认按 **I** 打开，按键可在游戏控制设置中修改；也可由有权限的管理员使用 `/gtit presets`。首次提示延迟 160 tick，按存档与玩家记录。专用服务器只有 OP4 收到提示并可配置，单人模式允许存档拥有者配置。

预设沿用现有贸易配置，作用于当前游戏实例或服务器。同一客户端的不同单人存档共用实例内的贸易配置；首次提示仍按各存档分别记录。

`MiaoTrade/<ID>.json` 位于实际游戏目录，专用服务器使用自己的实例目录。首次放入三个内置预设：

- `gtit-ae-basic`：AE 基础；与 AE 强化互斥。
- `gtit-ae-advanced`：AE 强化；与 AE 基础互斥。
- `gtit-base-decoration`：基地装饰。

三套内置预设来自 `E:\CodeGT\GT-MIAO-Web-BQ-Trade\workspace\gtit\` 下对应工作区的 `manifest.json` 中 `preset` 元数据及其贸易导出内容；`gtit-ae-basic` 为 123 笔交易、7 个页签，`gtit-ae-advanced` 为 239 笔、12 个页签，`gtit-base-decoration` 为 64 笔、2 个页签，共 426 笔交易、21 个页签。工作区位于 `workspace/gtit/<ID>/`，包含 `manifest.json`、`pages.json` 和 `tab_<ID>.json`，可在 Web 编辑器中编辑、保存和导出。输入页签与交易字段和编辑器导出结果逐字段深度比较通过，费用、数量、NBT、BQ 条件、依赖及顺序均保留。三个既有稳定 ID 与 AE 基础/强化互斥关系不变。`gtit-base` 和 `gtit-miao` 工作区没有 `preset` 字段，因此不会追加为内置贸易预设。

Web 编辑器导出的是 `config/gtit/trade/**` 配置，可用于检查和部署页面及交易。游戏预设使用的 `MiaoTrade/<ID>.json` 还包含预设 ID、名称、图标和互斥关系，不能将 Web 导出的 ZIP 或 `pages.json` 直接改名作为预设。历史候选原件与研究证据保留在编辑器仓库的 `plan/review/gtit-trade-presets-v1.8.93/`；当前内置资源采用上述 `preset` 元数据和编辑器导出交易内容。

内置资源的 AE 基础图标为 ME 控制器，AE 强化图标为 ME Drive。读取目录时，精确匹配原始空模板（包括旧 AE 图标版本）会自动升级为当前内置文件；用户改过的文件保留原样，并在 `MiaoTrade/builtin_updates/<确定性内容UUID>/<ID>.json` 保存新版副本。副本目录不参与预设扫描，UUID 由新版内容确定，重启不会重复堆积副本。预设窗口将已应用与待应用项分开显示；目录升级或刷新只更新可选目录，不安装贸易，仍需用户选择并点击应用才会安装和刷新默认贸易列表。操作触发窗口重建后仍会显示操作反馈。

可选择多个兼容预设。互斥关系以稳定 ID 声明，任意一方声明即生效。界面可从已有标签页制作新预设，填写 ID、名称、描述、互斥 ID 和幽灵物品图标。编辑、复制未启用的预设时默认保留原内容；明确切换后才从当前标签页替换内容。内置模板请使用新 ID 另存，已有自定义预设的 ID 固定。

应用会安装独立标签页。撤选只删除预设仍然拥有且完全未修改的页面与交易；已修改的页面保留为用户内容。保存、选择与重载具有版本冲突检测，磁盘事务日志用于中断恢复。绑定 BQ 的预设需要任务真实存在，缺失任务和卸载依赖 Mod 时不会放行。

## 关闭内置默认内容

编辑 `config/gtit/default_content.cfg` 后重启实例：

```text
defaults {
    B:loadDefaultTradeGroups=false
    B:loadDefaultLottery=false
    B:loadDefaultGifts=false
}
```

三个开关互相独立，默认均为 `true`。关闭后不注入相应内置内容，保留用户配置与礼包授予记录。贸易开关也覆盖旧 42 条交易的回退路径及 GTIT 自带贸易资产；自定义预设仍可使用。抽奖空配置保持为空，已经编辑过的卡池保留。礼包关闭不会使已经领取的有效包裹丢失；默认礼包库关闭时仍可只读查看默认版本和差异，但不能应用更新，也不会因此自动重新启用。

## 自动化验证入口

启用专用测试维度后可运行：

```text
gtitlab run native-gift-system
gtitlab run native-trade-presets
gtitlab run native-preset-catalog-check
```

前两个也包含在默认 `suite` 中。第三个只检查审核稿中的注册项、元数据及任务，不安装贸易。JSON 报告区分 PASS、FAIL、SKIP；服务端建树检查不能替代 Minecraft 物理客户端的视觉与点击验收，本文不将这类验收标记为已通过。
