# 猫猫售货机正面素材

这是离线预渲染再切片的资源流程。运行时仍只消费原有 `NEKOTV_FULL_OVERLAY` / `NEKOTV_FULL_OVERLAY_ACTIVE` 的 19 张方块贴图，不创建实体，也不调用世界或 GUI 猫渲染器。

## 来源与复现

- `cat-model.json` 由 `extract_cat_model.py` 读取本项目 Gradle 生成的 Minecraft 1.7.10 `ModelOcelot.java` 构造器提取：8 个部件、11 个 ModelBox，包含原始 pivot、box origin/size、纹理 offset。JSON 记录 ModelOcelot、ModelBox、TexturedQuad 三份实际源文件的 SHA-256。
- 猫使用原版 `red.png` / `black.png`，从 `build/rfg/mcp_patched_minecraft-sources.jar` 读取，并核对条目 SHA-256；没有手绘替代猫或把 Minecraft 源图另存进 mod。首次 clone 先执行本项目常规 Gradle 构建以生成该 jar。修改模型来源时再运行 `python tools/artgen_catalog/neko_tv/source/extract_cat_model.py`。
- 通用 CPU 透视、原 ModelBox UV、最近邻取样、深度缓冲和图层复合来自独立工具包 `../贴图复合渲染/src/texture_compositor`。`cat_scene.py` 只保留本场景的相机、原版站/坐姿和动作编排。
- `miao_coin.png` 继续使用项目原图的四帧，烘焙前核对 SHA-256。`materials.py` 在 16px 原生分辨率绘制木纹、金边，并保留控制器原电子面板/红绿指示像素；旧 NEKOVM 资源不覆盖。
- 在仓库根目录运行 `python -B tools/artgen_catalog/neko_tv/bake.py`。依赖 Pillow、NumPy、Python Playwright、Node.js 与已安装 Microsoft Edge；浏览器仅在烘焙时合成静态 SVG 背景、金币和预渲猫帧，不是游戏实时 renderer。Node.js 用于直接采样共享 `coin_flow.js`，核验错落轨迹和循环，不另行维护一份新轨迹算法。

## 布局与动作

画布 160×128，5×4 格，每格 32px；按从上到下、从左到右输出 19 片，跳过 `(row=3,col=2)` 的原生控制器。该格整周期 RGBA alpha 为零，预览另用新的木框控制器前脸合成。

上三行保留 8 条错落金币循环轨迹，币面缩小至约一格大小：四帧原图 alpha 宽高为 28×29、25×25、27×26、29×28px，统一用 35px 最近邻绘制，实际可见宽高依次为 31×32、28×28、30×29、32×31px，严格不超过一格 32px。160px 宽屏幕约能横放五枚此尺寸的币，但实际轨迹仍错落，不排成固定五列。金币严格裁剪至 y<96，原图、8 枚数量、差速、相位和 24 秒周期不变。底行左右各两格为带金色把手的闭合木抽屉，上方是实心连续暖木台面，没有黑色开口。红猫先从左柜背后探头，蹬腿跳上台面，再转成侧背朝向上方币幕，交替抬前爪向内侧扒拉金币。模型鼻尖和两只前爪均朝远离观众的 +Z，抬爪在画面投影中同时向右上移动，不是面朝观众伸爪。

黑白猫约 10.3 秒后从右柜背后探头，11.5–12.2 秒逐步把前爪搭上台面后沿；红猫约 11.2 秒察觉并转头受惊，12.2–13.7 秒先跳回柜后。黑白猫在 12.2–15.2 秒抓住台沿慢慢爬上：肩关节始终连接胸侧，前腿合理收放，由实际腿端反解整只猫的根部 Y/Z，使躯干随支撑爪拉起；双爪沿实心台面自然向前挪约 5px，左右后腿分两次抬脚蹬上，最后移到台面站姿。此段没有腾空或弹道上抛。黑白猫随后回望红猫离开处，16.2–17.3 秒转头看机器外侧，再以四肢交替步态沿台面向左走，21.2 秒抵达红猫原来的 x=36 位置，21.2–22.7 秒从左侧跳下藏回柜后。猫之间只有张望；左行开始前红猫已经离场，不触碰。

原版前腿是没有肘部的单段直 ModelBox。所有可见帧的前肩 pivot 仅沿用原版站/坐姿插值，不为抓点、扒拉或步行平移肩。红猫以竖起躯干、抬头及前腿适度外展配合短幅扒拉；根部同时补偿后爪高度，使后爪支撑台面。攀爬保持前腿从胸侧向前下方支撑，由根姿配合腿端，不再把整条前腿移到头/胸里面来锁死抓点。步行前腿缩小摆幅、后摆时适度外展，避免远端扫过胸部；左行仍使用与行程同步的四个完整步态周期。

红猫上台、红猫退场和黑白猫左侧退场这三段跳跃分别控制前爪、后腿、尾巴、头部与身体俯仰；根部在模型空间沿 Y/Z 弧线运动，同时有侧移。柜后探头按台面后沿 y=96 遮挡；抓握与上台时允许爪子显示在台面上，柜台前板 y=104 以下仍遮挡身体。台面先合成、猫随后、闭合前板最后，控制器格始终透明。

固定循环 24 秒、10fps、240 帧，`.mcmeta` 每帧 2 tick，与玩家、订单和机器业务状态无关。末端重复帧不输出。旧 6 片 API/资源不改，现有 19 片 API/顺序不改，仅替换其素材内容。

## 核验输出

`build/neko-tv-preview/verification.json` 记录逐片 PNG/frame hash、模型/贴图来源、240 帧回拼一致、控制器透明、底行金币开关差分一致、实心台面无暗槽、前板遮挡及 24 秒循环一致。叙事检查直接采样动画后的 ModelBox 部件：红猫鼻尖朝币幕、32 个完整伸爪帧的双爪朝 +Z 且投影右上；黑白猫 31 个攀爬采样帧均非腾空、双爪处于台面支撑范围、后腿错时抬起；39 个左行帧位置严格向左，出发跳下位置等于红猫原来的位置；三个跳跃段保留 Y/Z 弧线，并核对各动作连接处的实际部件连续性。`screen.png`、`screen.gif`、`contact-sheet.png`、带时间的 `motion-detail.png` 和 `key-*.png` 用于目检。

另运行 `python -B tools/artgen_catalog/neko_tv/source/foreleg_quality.py`，直接使用通用渲染器实际部件矩阵，核对所有 240 帧中 506 条可见前腿的肩关节和原始 box 内部采样。允许正常肩胸近端嵌合；头部检查排除前 2 模型单位的关节，胸部检查远端 6.25–9.75 单位。v2.0.18 负对照的肩位移最大 6.336、肩中心离胸体最远 5.872，头/胸远端采样最深分别 1.998/1.992 模型单位。修复后肩位移为 0，肩中心最多在胸表面外 0.2（在腿宽内保持连接），头/胸采样深度为 0.119/0.383 模型单位，按本画面约 1.8px/模型单位投影不足一个资源像素；保留天然表面接触，不声称完全零交叠。场景坐标点与实际渲染矩阵的最大误差约 6.3e-15。`build/neko-tv-preview/foreleg-fix/geometry.json`、`before/after-colored-contact.png`（红/蓝为左右前腿、黄为头、绿为胸）及 `compare-reach.gif` / `compare-climb.gif` 保存同角度近景对照；通过 `--baseline <旧cat_scene.py>` 可复现负对照。这些均为离线几何采样与资源预览，不是 Minecraft 实拍、完整实体物理碰撞证明或结构/运行测试。
